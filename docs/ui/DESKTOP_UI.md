# MOBO Desktop 界面说明

桌面界面源码位于仓库根目录 [`work_platform/`](../../work_platform/README.md)，采用 PySide6，面向 Windows
DEFORM 计算机和远程 DOE 服务两种部署方式。界面不是新的算法层：本地自动化直接调用
`mobo.automation` 的任务定义与流水线，代理模型和优化通过
[`DOE_HTTP_API.md`](../api/DOE_HTTP_API.md) 访问后端。

## 信息架构

| 工作区 | 主要职责 | 执行位置 |
|---|---|---|
| 工作台 | 展示推荐流程和平台边界 | 本地界面 |
| 单工步计算 | 抽样、KEY 生成、求解、增量提取、批处理进度 | 本地 Python / DEFORM |
| 多工步批处理 | 联合抽样、连续换模、检查点与逐样本工步状态 | 本地 Python / DEFORM |
| 代理模型 | TXT/TSV/CSV 数据预览、演示数据生成、五类模型训练、模型评价结果对比 | DOE HTTP 服务 |
| 优化中心 | 单目标、多目标 NSGA-II 与 PPO 强化学习 | DOE HTTP 服务 |
| 结果分析 | 已完成优化任务直载、宽表、任意字段 X/Y/Z 映射、可缩放二维/三维图表、导出 | 本地界面 / DOE HTTP 服务 |

## 交互约定

- 顶部提供全局“显示模式”切换，并记住上次选择。工程深色模式保持现有监控工作台风格；论文科研
  模式参考 DEFORM/CAE 工业软件，采用分层浅灰工作区、深灰控件边框和独立的数值框按钮区，并在
  页眉展示华中科技大学官方组合标识。官方标识只用于应用身份区域，不覆盖数据点或作为图表水印。
- 显示模式不是单纯更换控件皮肤：代理模型评分图、结果分析二维图、Matplotlib 三维图以及已经
  打开的独立图表窗口都会同步刷新背景、文字、网格、数据系列和边线颜色。论文科研图表保留白色绘图区、
  深色文字、浅灰网格及华科蓝为主的印刷友好色组；坐标、数值和抽样逻辑保持不变。
- 两套模式使用一致的颜色语义和中等圆角：蓝/青表示选中与主操作，绿色表示成功，黄色表示警告，
  红色仅用于错误、停止、删除等危险操作，灰色表示禁用和辅助信息。科研浅色导航使用华科蓝游标，
  工程深色导航使用青蓝游标；结果页每个操作区只保留一个高强调主按钮。
- 左侧导航移除数字序号，并按流程分为默认展开的“工作台”和“优化模块”两组。“工作台”下包含
  工作台概览、单工步计算和多工步批处理；“优化模块”下包含代理模型、优化中心和结果分析。
  点击组标题只切换子菜单展开状态，不改变当前页面。
- 计算、训练、优化均不在 UI 主线程执行；界面在运行期间保持可操作。
- 两套主题为单行输入框、下拉框和数值框保留最低内容高度；优化中心在可用高度不足时滚动展示，
  避免窗口缩小或显示缩放后表单文字被纵向裁切。
- 状态统一映射为未开始、排队中、运行中、正在停止、已停止、已完成和失败。
- 后端返回的带时区 ISO 时间统一转换为运行界面的工作站本地时间，并显示为
  `YYYY-MM-DD HH:MM:SS`；阶段和最近更新时间分行展示，避免窄状态卡片拥挤换行。
- 训练与优化按 1.5 秒轮询后端，进入终态后自动停止轮询。
- 代理模型页把 DOE 状态同步、配置保存和训练运行作为独立状态：同步期间只暂缓训练提交，仍允许
  保存数据与字段定义；只有实际训练排队、运行或停止过程中才拒绝修改配置。
- DOE 列表刷新和训练状态查询均合并重复请求；按钮在请求完成前显示忙碌状态，连续点击不会创建
  并发工作线程或反复重建组合框。过期状态响应结束后会为当前选择补发一次查询。
- DOE 选择使用任务 ID 与单调递增的选择版本共同校验异步响应；快速切换任务时，旧请求完成后
  不得覆盖当前任务的字段、状态或结果。启动按钮要求数据/训练字段和配置就绪，停止按钮只在
  排队或运行状态可用。
- DOE 列表刷新后默认保持未选择，代理模型与优化中心均使用只读任务下拉框；新任务只能通过
  “新建 DOE”创建，并在创建成功、列表刷新后选中。代理模型页可删除当前 DOE，删除前明确提示
  会永久清理训练数据、代理模型、优化记录和结果；运行中的任务必须先停止，删除请求期间禁用任务
  选择和重复操作。只有用户主动选择任务后才读取后端持久化状态。检测到已完成训练且存在模型记录时，界面提示模型可直接
  用于优化并显示“重新训练”；检测到已完成优化且存在结果时显示“重新优化”。两种重跑操作
  均在提交前再次确认，失败、停止或未开始的任务仍显示普通启动按钮。重新提交后，优化按钮在
  排队和运行阶段统一显示“正在优化…”并保持禁用，避免误导用户再次提交。
- 代理模型训练提交后，启动按钮在排队和运行阶段显示“正在训练…”，停止阶段显示“正在停止…”。
  状态说明按排队、训练、交叉验证、停止、失败和完成分别渲染，不得在运行期间显示“尚未开始训练”；
  后端返回当前模型及序号时显示如 `DNN（5/5）`，便于区分耗时模型与界面卡死。
- 代理模型页按输出目标生成独立标签页，每个标签页直接为 PRG、SVR、RF、KM 和 DNN
  提供勾选框与“参数”按钮。每个输出独立保存模型选择和对应超参数，因此同一模型族可在
  两个输出上使用不同参数；开始训练前要求每个输出至少选择一个候选模型。参数表单由后端
  `GET /api/v1/hust/doe/train/hyperparameters` 元数据生成；留空或选择“使用默认值”时不提交覆盖值，
  用户显式设置的逐输出参数通过 `target_models` 随训练请求发送，并在重新进入 DOE 时恢复。
  未勾选模型的参数按钮禁用，参数
  元数据加载失败时按钮显示“参数（重试）”并可重新请求，仍允许按全部默认参数训练。
- 训练数据、字段评价和逐输出模型的固定说明收纳到标题旁的问号帮助按钮中，
  避免长提示挤占操作区。输出目标较多或名称较长时，标签栏提供左右箭头和鼠标滚轮切换，
  标签悬停提示保留完整输出名称。数据预览、评分对比和任务定义等其他标签页也使用相同的防溢出交互。
- 界面使用“评价划分数”避免把1误解为标准一折交叉验证。设为1时，提交一次固定随机种子的
  80%训练/20%测试留出评价，显示的 R² 来自20%测试集；不小于2时使用 K 折交叉验证，每次一折测试、其余 K-1 折训练。
- 模型评分图默认按输出目标汇总，每个输出只显示当前指标下的最佳候选模型；
  悬停柱子显示完整分数，点击输出后下钻到该输出的各候选模型对比，并可返回总览。
  评价指标可切换综合评价分数、决定系数 R² 和归一化误差得分 `1/(1+NMAE)`，
  默认为综合评价分数，三项均按“越高越好”选择最佳模型。组合模型 `MIXED` 不重复计入候选模型对比。
- 训练状态卡不将多输出任务概括为单一“当前最佳模型”。单输出时显示最佳模型族和 R²；
  多输出时显示“逐输出推荐模型”、已选模的输出数量以及各模型族的使用数量，并明确推荐结果按各输出 R² 选择。
- 代理模型页在 DOE 下提供训练历史选择；每次训练的数据副本、模型、标准化器、评分和最佳模型
  都按独立轮次保存。切换历史只读取该轮次，不会被之后的重新训练覆盖。
- “模型预测”页签跟随当前训练历史，允许指定该轮的普通候选模型或逐输出组合模型；支持编辑
  单条/批量输入、添加和删除样本、载入训练数据首行，并展示各输出预测值。性能区同时显示服务端
  总耗时、模型加载耗时、纯预测耗时、单样本耗时及包含 HTTP 通信的桌面端端到端耗时。
- 优化中心的 DOE 控件为只读下拉框，只允许选择后端列表中的已有任务；没有可用任务时显示空占位，
  不允许输入任意标识启动优化。下拉项只显示唯一任务名称，DOE ID 保存在控件内部用于接口调用；选择后从训练进度接口恢复
  输入字段、训练数据最小/最大边界及输出目标，替代固定演示字段。
- 优化中心在 DOE 下选择已完成训练轮次，启动请求携带 `training_run_id`；候选模型和字段边界
  都来自该轮次，保证优化结果可以追溯到唯一训练版本。
- 选择训练轮次后，“配置逐输出模型”打开独立窗口，每个输出占一行，可从该输出已训练的
  PRG、SVR、RF、KM 和 DNN 候选中独立选择。默认按该输出 R² 从高到低排列并选中首项；用户可改为
  任意其他候选。主界面只显示已配置数量和模型族分布，问号中展开完整的“输出 → 模型族 → R²”。
  启动时提交覆盖全部输出的 `target_model_ids`；后端按输出分别加载模型、X/Y 标准化器和参数，不再使用统一模型或旧组合模型兼容选项。
- 优化配置中的训练轮次、代理模型配置、优化模式、优化算法和算法参数均提供问号帮助；
  NSGA-II 和 PPO 参数编辑器也提供单项悬停说明。目标函数与设计变量卡片说明字段来源、方向、权重和边界的作用。
- 任务状态卡提供“查看收敛曲线”按钮，通过优化过程接口读取当前或最近优化轮次。曲线在独立窗口
  只绘制一条，单目标为最佳加权目标值，多目标为HV，强化学习为平均回合奖励；遗传算法横轴为
  迭代代数，强化学习横轴为已完成训练回合数。
  显示运行版本、状态、记录点和优化方向，支持滚轮/框选缩放、双击重置及手动刷新；窗口打开且
  优化仍在运行时随状态轮询自动刷新，并跟随工程深色/论文科研模式切换图表主题。
- NSGA-II 与 PPO 参数弹窗均提供收敛早停设置。默认启用，末端窗口为10个有效记录点、最少
  观察20个有效记录点、变化率阈值为5%；单目标检查历史最佳可行加权目标，多目标检查HV，
  PPO检查最近100回合平均累计奖励。收敛曲线弹窗显示实际早停点和末端变化率。
- 目标方向通过枚举编辑器限制为最小化/最大化，权重和变量边界使用数值编辑器。表格修改后立即
  检查重复名称、权重范围与总和、上下界关系；超出训练数据范围时显示黄色风险提示。
- 优化配置卡片只显示当前算法参数摘要和“设置参数”入口；点击后在独立模态窗口中编辑，避免窄卡片
  压缩数值与步进按钮。NSGA-II 使用种群规模、子代数量和迭代代数；PPO 使用训练时间步、每回合
  步数、评估回合数、学习率和约束惩罚系数。弹窗支持取消回滚和恢复当前算法默认值，切换模式时
  只显示并提交对应算法的参数。
- 页面导航完全由用户控制。优化中心读取到历史完成结果时只更新状态和按钮，不加载结果，也不
  自动跳转到结果分析；结果需在结果分析页中手动选择任务后加载。
- 顶部连接检测使用 Qt 异步网络请求和完成信号，不占用计算线程池；3 秒无响应即判定不可用，
  检测期间忽略重复点击。
- DEFORM 真实运行前可用演练模式核对路径与 KEY 生成；真实执行仅支持已安装 DEFORM 的 Windows。
- 结果数据默认保留原始表格，图表只是同一数据的可切换视图，不替换数值结果。
- 训练预览、目标函数、设计变量和结果表采用可拖动表头列宽；字段超出可见宽度时使用横向滚动。
  结果表采用 `QAbstractTableModel` 虚拟读取，不为每个数据单元创建 `QTableWidgetItem`。
  目标函数和设计变量表可添加空行，也可选择一行或多行后删除。
- 结果分析可列出后端状态为 `optimization_finished` 的 DOE，并通过结果 `resource_id` 和统一
  数据接口直接加载字段与数值；同一 DOE 的多次优化以独立运行版本保存，界面展示状态、模式、
  算法、解数量、耗时和更新时间；运行版本下拉框与摘要表均提供纵向滚动，并允许加载任一完成版本。
  用户手动选择任务后，界面自动加载历史并显示最近完成版本；新一轮优化处于排队、运行、失败或
  停止状态时，仍从历史中回退加载最近一次成功结果。历史列表与结果资源分两步读取，因此单个
  结果资源读取失败不会清空运行历史。主结果页不嵌入历史表格或版本下拉框，只保留“查看运行历史”
  按钮；独立历史窗口展示完整表格，并支持选择、双击或点击按钮加载已完成版本。界面不读取或暴露
  服务端优化目录路径。本地文件仍作为补充入口。
- 优化结果默认显示二维散点图，避免用折线暗示优化解之间存在顺序；用户选择折线图时，数据按 X
  排序后连接。二维坐标轴显示字段标题、六位有效数字标签和带边距的数据范围，X 轴变化过小时给出
  可理解的提示。散点属于同一组优化可行解，因此隐藏单系列图例；坐标含义仅由 X/Y 轴标题表达。
- 二维图支持滚轮、矩形框选和按钮缩放；三维散点使用嵌入式 Matplotlib Qt 画布，避免原生
  OpenGL 子窗口在部分 Windows 显卡驱动上阻塞或退出，并支持滚轮缩放、拖动旋转、按钮缩放及
  重置视图。三维坐标标题优先使用系统中文字体（微软雅黑、黑体或宋体），并预留固定绘图边距，
  避免中文缺字方框和长字段名称触发布局警告。
  “单独查看图表”或双击二维图会创建独立大窗口，二维和三维图在独立窗口中仍保留各自的缩放与
  旋转操作。
- 图表坐标轴不绑定字段角色：输入工艺参数、输出目标和其他数值辅助列均可任意映射到
  二维 X/Y 或三维 X/Y/Z；非数值行会从当前图表中跳过，但继续保留在原始表格中。
- 为保持大数据交互流畅，二维折线/散点最多均匀抽样 2000 点，三维散点最多 1000 点，柱状图最多
  80 点；控制区显示原始有效点数与实际绘制点数，表格和导出仍使用完整数据。
- 数据导入会把 `NaN`、正负无穷和非数值单元格视为无效值。训练数据自动移除全无效列并
  排除仍含无效值的行，同时在界面显示清理统计；结果分析保留原表，但从坐标轴选择器排除
  全无效列，单个图表仅跳过当前坐标组合中的无效行。
- 单工步与多工步的 LHS 抽样提供“追加边界组合”选项。界面默认不勾选，严格生成用户指定的
  样本行数；勾选后追加所有参数上下界的笛卡尔组合并去重。
- 单工步与多工步页面提供独立的用户任务模板库。内置任务是只读预设，可修改后以新的唯一 ID 和
  名称另存为用户模板；也可点击“新建模板”从空白定义开始。用户模板可保存、重新加载、更新和删除，
  删除模板不删除已经生成的样本、KEY、DB 与结果。模板文件保存在本机数据目录，不依赖 DOE HTTP 服务。
  用户可在界面填写任务 ID 和名称，并通过“工步模板、输入参数、输出目标”三类配置生成当前任务：
  单工步可选择一个 KEY 模板；多工步可增删工步、分别选择 KEY 模板，并设置材料继承、晶粒开关和
  可选位置偏移。输入参数可增删并选择后端已注册的参数类型、作用对象和上下界；一个数值需要同步
  多个对象时用逗号分隔。输出目标可配置输出列名、提取目标、对象、适用工步、分量、全过程提取和
  工件类型。保存和运行前均校验 ID/名称唯一性、KEY 文件与多工步结构、参数能力、对象、范围、
  工步引用、输出列名及目标提取能力。预设切换会重新填充编辑器，表格中的当前值直接用于抽样、
  KEY 生成、计算和结果提取，不会改写内置预设。
- 代理模型评分柱状图在柱内直接显示简洁分数；悬停或点击柱子时主动弹出模型名称和六位小数
  完整分数，并在图表下方保留当前悬停或选中的模型与分数。
- 无表头数据先使用“字段 1、字段 2……”作为临时名称。选择文件后，清洗后的数据副本立即上传并
  绑定到当前 DOE。用户可逐列修改名称并指定输入/输出角色；修改后界面明确提示尚未保存，并提供
  “保存 DOE 配置”按钮。保存操作独立更新训练数据、
  字段名称、输入/输出角色及输入边界，不会启动训练；后端不猜测物理含义，优化中心自动复用
  已保存或实际训练使用的字段名称。
- 再次选择已保存 DOE 时，界面通过数据 `resource_id` 从后端恢复完整表格、字段顺序和输入/输出
  角色；数据框显示原文件名与“DOE 副本”标识，不保存客户端绝对路径。切换到另一 DOE 时清空
  上一个任务的数据上下文，避免把旧任务表格误保存到新任务。
- DOE 列表和周期状态读取失败时在页面内显示错误原因和重试提示，不使用静默失败；提交类错误仍
  使用对话框提醒。

安装、启动和操作入口见 [`work_platform/README.md`](../../work_platform/README.md)。HTTP 请求字段与状态响应仍只在
[`DOE_HTTP_API.md`](../api/DOE_HTTP_API.md) 维护，本文不复制协议正文。


### GH4169 六参数使用

单工步页面选择“GH4169碾环单工步任务1”，输入参数表自动载入六个参数及默认范围；
可编辑上下限，固定值输入时把上下限设为同一数值。参数表悬停说明展示物理含义和单位。
在新工作区生成 LHS/全因子样本，或选择按当前六列顺序编写的无表头 TSV，再点击生成 KEY、
运行计算。所有生成样本统一保留两位小数。预设可另存为唯一 ID/名称的用户模板并重新加载。
温度修改对象 1～5 的 NDTMP，接触参数共同作用于四组工件–模具接触；完整映射见
[关键字说明](../deform/DEFORM_KEY_KEYWORDS.md#gh4169-六参数任务2026-10-27)。

不要把旧三列 GH4169 样本用于新任务。已有 KEY 与当前配置不一致时界面会报告失败，须改用新工作区；
KEY 生成、求解或结果提取失败时不会显示“批处理已完成”。

本机控制程序同目录安装64位求解引擎时，运行目录自动配置 `64bit.DAT`；空求解消息和未完成模拟不会显示成功。


### 单工步分批计算

单工步页面可直接选择无表头 `.tsv` 或 `.txt` 样本文件，列顺序必须与当前输入参数表一致。
模板加载时自动选择样本目录里最近的 TSV/TXT 文件。

在“执行与进度”中勾选“指定样本范围”，填写从1开始、包含两端的起始与结束编号。
例如300条样本中，`1～100` 计算前100条，`101～200` 计算第二批100条，`201～300` 计算最后100条。
不勾选时处理全部样本；超出文件样本数或起始大于结束时立即报错。范围不改变抽样生成的总行数。

“仅生成 KEY”“启动 / 继续运算”“提取结果”和进度查询均使用同一个范围，原始样本文件不拆分、
不重排。生成文件保留原文件中的全局样本编号，界面进度按从1开始的样本编号显示。
不同范围分别保存进度、增量状态与结果；重新打开后使用相同工作区、相同完整样本文件和相同范围续跑。
运行期间范围、输入文件、工作区及运行选项会禁用，避免过程中改变本次配置。


### GH4169 固定终态行程

芯辊峰值速度仍在0.1～2.5 mm/s抽样；五点进给曲线的时间节点随速度反比例缩放，使总进给为14.5 mm，
并同步调整时间上限、必要时提高步数上限，保持原时间步长。界面参数悬停说明注明等行程控制。
求解完成后自动核对DB最新结果集的实际压力辊行程（14.5 mm，容差0.01 mm）；未达标时不会显示该批模拟完成。
独立提取结果也会校验行程并报告失败。已有300条六列TSV可以继续使用；旧版生成的KEY和DB不可混用，
请选择新工作区重新生成KEY并计算。该检查保证只有达到行程要求的结果被接受，不替代数值收敛检查。

### 停止 DEFORM 批处理与中断恢复

单工步与多工步页面的“停止计算”会停止当前工作台内所有运行批次：先取消后续样本/工步的提交，
再终止已登记的 DEFORM 求解器及前处理进程树。按钮进入“正在停止”，等待工作线程退出后显示
“已停止”，随后可以再次点击“启动 / 继续运算”。已完成结果保留，中断样本不标记为完成。
工作台以外独立启动的 DEFORM 任务不在此按钮的管理范围内。

DEFORM 计算过程中会把数据库暂命名为 `FOR003`，停止/结束时才恢复原 DB 文件名。
因此不得把 `FOR003` 当作垃圾文件删除。再次启动时，程序先检查数据库是否仍被存活求解器使用；
在副本上读取最新实际保存步，通过 `DBREAD 0` 和 `GENDB 1 1 0` 生成可续算的负步号，
校验通过后恢复为目标 DB。原始 FOR003、旧 DB 和残留锁文件归档在该工况目录的 `recovery/`。
恢复失败时同样保留原件，并自动从该样本原始参数化 KEY 重新生成 DB，重新计算该工步。
只能恢复到已保存的数据库状态，停止瞬间尚未保存的迭代不能保留。

续跑应使用同一完整样本文件、模板、工作区和样本范围。修改工艺定义后请使用新工作区；
既有数据库中的运动控制不会因代码升级而自动变为新的等行程控制。
