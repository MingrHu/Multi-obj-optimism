# UI 可靠性与大数据性能 ExecPlan

本计划是优化工作流改进的第二阶段，覆盖前一轮评估中的第 4～10 项。实施期间持续更新
`Progress`、`Surprises & Discoveries`、`Decision Log` 和 `Outcomes & Retrospective`。

## Purpose / Big Picture

桌面端需要在快速切换 DOE、后端失败和大规模结果数据下保持状态可信、界面可操作。完成后，过期
异步响应不会污染当前任务；启动和停止按钮只在合法状态可用；结果表不再为每个单元格创建控件；
图表对超大数据自动抽样；NSGA-II 与 PPO 使用含义明确的独立参数面板；刷新失败在页面内可见。

## Surprises & Discoveries

- 只比较 DOE ID 仍不能完全覆盖 `A → B → A` 的快速切换，因此训练和优化页同时保存单调递增的
  选择版本；响应必须同时匹配 DOE ID 和版本才能更新界面。
- 大表卡顿的主要成本不是横向滚动，而是 `QTableWidgetItem` 的逐单元格实例化。结果表改用
  `QAbstractTableModel + QTableView` 后，五万行数据只保留原始二维列表，单元格按需读取。
- 柱状图已有 80 点截断，但折线、散点和三维散点没有上限；统一的均匀抽样需要保留首尾数据，
  同时在界面明确显示原始有效点数和实际绘制点数。

## Decision Log

- Decision：二维折线/散点最多绘制 2000 点，三维散点最多绘制 3000 点，柱状图最多显示 80 点。
  Rationale：保留趋势和交互流畅度，完整数据始终保留在虚拟表格与导出文件中。
- Decision：结果表使用只读虚拟模型，训练预览和配置编辑表继续使用 `QTableWidget`。
  Rationale：前者面向大规模只读数据，后两者需要有限行数的直接编辑和委托控件。
- Decision：NSGA-II 暴露种群、子代和迭代代数；PPO 暴露时间步、回合步数、评估回合、学习率和
  约束惩罚系数。
  Rationale：控件名称与后端参数一一对应，避免把不同算法概念压缩进同一字段。
- Decision：列表和状态读取错误采用页面内提示并保留重试入口，提交失败仍使用对话框提醒。
  Rationale：轮询/刷新失败可能短暂发生，不应反复弹窗打断操作，但不能静默隐藏。

## Validation and Acceptance

1. 快速切换 DOE 后，旧任务的训练字段、训练状态和优化状态响应被忽略。
2. 未选择 DOE、训练字段未就绪、配置无效或任务运行中时不能启动；仅排队/运行时可停止。
3. 五万行结果由虚拟模型展示，列宽可拖动且支持横向滚动。
4. 二维和三维数据超过上限时均匀抽样，并显示原始点数与展示点数。
5. GA/PPO 切换显示各自参数，提交载荷不混入另一算法的字段。
6. DOE 刷新失败显示错误原因与重试提示。

## Outcomes & Retrospective

第 4～10 项均确认存在并已修复。选择版本令牌覆盖训练、优化提交及轮询回调，结果加载也按当前
DOE 和运行版本校验。训练/优化按钮由任务状态、数据/训练字段和配置有效性统一驱动。

结果表已经虚拟化；二维图上限 2000 点、三维图上限 3000 点，柱状图上限 80 点，并在图表控制区
展示抽样说明。优化参数面板按算法拆分，刷新错误可在训练或优化页内直接看到并重试。
