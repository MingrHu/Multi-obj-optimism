# DEFORM KEY 关键字与仓库对应关系

本文总结当前仓库在 DEFORM-3D V11 KEY 文件生成、参数替换、结果提取和多工步衔接中实际使用的关键字。

本文不是 DEFORM 全量关键字手册。部分关键字的字段会随对象类型、运动控制方式和分析模块变化；表中的“仓库行为”以当前代码和 TC4 环轧模板为准。

## 1. KEY 文件基本结构

KEY 文件是按行组织的文本文件，常见形式为：

```text
KEYWORD    object_id    field_1    field_2    ...
```

- `*` 开头的行是注释或分段标记。
- 关键字通常位于第一个字段。
- 对象相关行通常以第二个字段表示对象 ID。
- 数值常使用 DEFORM/Fortran 风格科学计数法，例如 `9.5000000000E+002`。
- 当前仓库生成数值时统一使用 10 位小数尾数和 3 位指数。

典型对象编号约定如下：

| 仓库对象名 | 对象 ID | TC4 环轧模型中的含义 |
|---|---:|---|
| `workpiece` | 1 | 可变形环件 |
| `driving_roll` | 2 | 驱动辊 |
| `pressure_roll` | 3 | 压力辊/芯辊 |
| `axial_roll_1` | 4 | 轴向辊 1 |
| `axial_roll_2` | 5 | 轴向辊 2 |
| `topdie` | 2 | 普通锻造模型中的上模别名 |
| `butdie` | 3 | 普通锻造模型中的下模别名 |

对象编号是当前模板约定，不是 DEFORM 对所有工程强制规定的编号。更换模板时必须确认对象 ID。

## 2. 样本参数与 KEY 关键字映射

以下映射由 `mobo.replacement` 注册，并由 `automation.keyfile` 路由调用。

| 样本参数名 | KEY 关键字 | 当前替换方式 | 常用对象 |
|---|---|---|---|
| `roll_tmp` | `REFTMP` | 匹配关键字和对象 ID，替换行末值 | `workpiece` |
| `temp` | `NDTMP` | 匹配关键字和对象 ID，替换行末值 | `workpiece` |
| `speed` | `MOVCTL` | 匹配关键字和对象 ID，替换行末值 | `topdie` 等 |
| `driving_roll_rad_speed` | `ANGMOV` | 匹配关键字和对象 ID，替换行末值 | `driving_roll` |
| `pressure_roll_speed_lower` | `MOVCTL` 控制点块 | 与上界共同缩放控制点速度列 | `pressure_roll` |
| `pressure_roll_speed_upper` | `MOVCTL` 控制点块 | 与下界共同缩放控制点速度列 | `pressure_roll` |
| `workpiece_temperature` | `REFTMP` + `NDTMP` | 同时更新工件参考温度和统一节点温度 | `workpiece` |
| `pressure_roll_constant_speed` | `MOVCTL` | 仅用于常速模式，替换行末速度 | `pressure_roll` |

### 2.1 `REFTMP`：对象参考温度

示例：

```text
REFTMP       1    1.2000000000E+003
```

在当前环轧模板中：

- 第二个字段 `1` 是工件对象 ID。
- 最后一个字段是该对象的参考温度。
- `roll_tmp` 使用这个关键字替换工件温度。

模具也有自己的 `REFTMP`，例如驱动辊对象 2、芯辊对象 3。替换时必须同时匹配对象 ID，不能只查找关键字。

### 2.2 `NDTMP`：节点/工件温度数据

示例：

```text
NDTMP        1       0    1.2000000000E+003
```

当前普通单工步参数 `temp` 映射到 `NDTMP`，并替换末字段。它和 `REFTMP` 不是完全相同的概念：

- `REFTMP` 是对象属性中的参考温度。
- `NDTMP` 位于对象状态数据中，表示节点温度数据或统一节点初始温度。

模板中可能同时存在二者。实际采用哪个关键字，应以该模板的初始化方式为准。

TC4 多工步任务使用 `workpiece_temperature`，因为后续工步在上一工步 DB
状态上换模。过渡动作会同时应用 `REFTMP` 和参数化后的
`NDTMP 1 0 <temperature>` 片段，避免只改参考温度而未设置继承工件温度。

### 2.3 `MOVCTL`：平移运动控制

`MOVCTL` 表示对象的平移运动控制，是当前仓库最需要谨慎处理的关键字。

常量运动示例：

```text
MOVCTL       3       1       0    0.0    1.0    0.0    3.0000000000E-001
```

在当前 TC4 模板中可理解为：

- `3`：对象 ID，即压力辊/芯辊。
- 中间字段：运动控制模式以及运动方向。
- `0.0 1.0 0.0`：沿 Y 方向运动。
- 行末 `0.3`：该常量运动形式下的速度/进给参数。

控制点函数形式示例：

```text
MOVCTL       3       1       2    0.0    1.0    0.0       3
    1.0000000000E+000    2.2000000000E+000
    2.0000000000E+000   -3.0000000000E-001
    3.0000000000E+000    8.0000000000E-001
```

在这种形式下：

- `MOVCTL` 行末的 `3` 是后续控制点数量，不是速度。
- 后续 3 行分别保存自变量和速度值。
- `pressure_roll_speed_lower/upper` 不修改 `MOVCTL` 头行。
- 仓库先扫描后续控制点速度绝对值范围，再线性映射到样本给定的上下界，并保留原正负号。

因此，不能对所有 `MOVCTL` 都简单替换最后一个字段。通用参数 `speed` 只适合末字段确实是速度的简单模板；函数控制应使用专门的文档级原子能力。

### 2.4 `ANGMOV`：角运动控制

示例：

```text
ANGMOV       2       1       0    1.2000000000E+000
```

当前仓库使用 `driving_roll_rad_speed` 替换行末值，用于设置驱动辊角速度。具体单位受 KEY 文件单位制和时间单位控制，不能脱离工程单位设置单独判断。

## 3. 对象、材料与几何关键字

### 3.1 `OBJTYP`：对象类型/对象槽控制

模板示例：

```text
OBJTYP       1       2       0
OBJTYP       2       1       0
```

在当前模板中观察到：

- 对象 1 的类型值 `2` 对应可变形工件。
- 对象 2～5 的类型值 `1` 对应刚性模具。

多工步过渡动作中还会出现：

```text
OBJTYP 2 0
```

它用于在前处理动作上下文中准备/重定义对象槽，然后通过 `KFREAD` 载入下一工步模具。动作文件中的短格式不应直接按完整模板的物理对象类型字段解释。

### 3.2 `OBJNAM`：对象名称

示例：

```text
OBJNAM       1
Workpiece - Ring
```

对象名称位于关键字下一行。圆度提取逻辑可根据 `OBJNAM` 查找工件，也可以直接指定对象 ID。

### 3.3 `MTNAME`：材料名称

示例：

```text
MTNAME       1
ALUMINUM-7075[750-1000F(400-550C)]
```

它定义材料编号对应的名称。名称后的材料性能数据通常由其他关键字继续描述。

### 3.4 `FSTRES`：流动应力数据

`FSTRES` 开始一段材料流动应力/本构数据。该数据通常与应变、应变率和温度有关。当前仓库不修改它，但批处理时必须保证材料模型与实际合金一致。

### 3.5 `DIEGEO`：对象边界/模具几何数据

示例：

```text
DIEGEO       2       1    1600    3200
```

它标记对象的边界几何数据块。虽然名称包含 `DIE`，当前模板的可变形工件对象也可能出现 `DIEGEO` 边界描述。

多工步实现把对象 1 的第一个 `DIEGEO` 作为工程切分点：

- 保留 `DIEGEO` 之前的对象 1 控制属性。
- 不加载下一模板中的对象 1 几何和网格。
- 继续使用前一工步 DB 内已经变形完成的工件。
- 对象 2～5 则加载完整片段，包括新模具的 `DIEGEO`。

这个切分规则适用于当前标准 TC4 KEY 结构，不代表所有 DEFORM 模块都必须以第一个 `DIEGEO` 作为唯一切分边界。

### 3.6 `RZ`：节点编号与坐标

示例：

```text
RZ           1   16200
```

- `1`：对象 ID。
- `16200`：后续节点记录数量。
- 后续每行通常为 `node_id x y z`。

当前圆度提取器读取工件的 `RZ` 坐标，构造三维网格截面。

### 3.7 `ELMCON`：单元连接关系

示例：

```text
ELMCON       1   13080       8
```

- `1`：对象 ID。
- `13080`：单元数量。
- `8`：每个单元的节点数。
- 后续每行是单元编号及其节点编号。

当前圆度实现只支持 8 节点六面体单元，通过 `RZ + ELMCON` 提取截面内外轮廓并计算圆度。

### 3.8 `CNTRAX`：对象中心、旋转轴与姿态信息

示例：

```text
CNTRAX       1    0.0    0.0    176.0    0.0    0.0    1.0    0.001
```

该行包含对象编号、中心位置、轴向和附加姿态/转动状态字段。当前多工步代码只读取：

```text
tokens[2:5] -> x, y, z
```

然后计算：

```text
下一模板工件中心 - 前一工步终态工件中心 = OBJPOS 平移量
```

当前实现没有根据 `CNTRAX` 计算完整旋转矩阵，也没有自动做模具间隙或干涉校验。

## 4. 接触关键字

### 4.1 `FRCFAC`：对象间摩擦参数

示例：

```text
FRCFAC       1       2       1       0    7.0000000000E-001
```

表示对象 1 与对象 2 接触对的摩擦设置，末字段为当前模板中的摩擦系数/摩擦因子。当前仓库尚未把它注册为可采样替换参数。

### 4.2 `IHTCOF`：接触传热系数

示例：

```text
IHTCOF       1       2       0    5.0000000000E+000
```

表示对象接触对之间的界面传热参数。当前仓库会在多工步切换时随 `Inter-Object Data` 整段加载，但不会单独修改。

### 4.3 `INICTC`：初始化接触

多工步过渡动作使用：

```text
INICTC 1
```

在新模具和继承工件装入后重新初始化接触搜索。它不能保证几何一定没有干涉；若前一工步参数导致形状偏差过大，仍可能出现初始穿透、接触丢失或重网格异常。

## 5. 求解和停止控制关键字

### 5.1 工程与分析类型

| 关键字 | 含义 | 说明 |
|---|---|---|
| `TITLE` | 工程标题 | 实际标题通常位于下一行 |
| `SMODE` | 模拟模式 | 数值含义由 DEFORM 模块定义，当前仓库不修改 |
| `STYPE` | 分析/工艺类型 | 当前环轧模板为 `6`，不要在不同模块间直接照搬 |
| `UNIT` | 单位制编号 | 决定长度、时间、温度、力等字段的解释 |
| `TRANS` | 传热/变形耦合等过程开关 | 当前仓库随模板保留 |
| `OPRNAM` | Operation 名称 | 名称位于下一行 |
| `SIMNAM` | Simulation 名称 | 名称位于下一行 |

### 5.2 步进与停止条件

| 关键字 | 含义 | 当前仓库用途 |
|---|---|---|
| `NSTART` | 起始步编号 | 终态 KEY 中可用于观察已完成步数 |
| `STPINC` | 结果保存/步进增量设置 | 随模板保留 |
| `PDIE` | 主驱动模具/参考模具设置 | 环轧模板中常指对象 3，仓库不修改 |
| `NSTEP` | 最大计算步数 | 作为上限；TC4 模板为 99999 |
| `DTMAX` | 最大时间步长 | 当前 TC4 模板为 0.01 |
| `DPLEN` | 位移/步长相关控制参数 | 随模板保留 |
| `ODMAX` | 最大外径停止条件 | 环轧达到目标直径时正常停止 |
| `TNOW` | 当前模拟时间/行程状态 | 终态 KEY 中记录已推进状态 |

TC4 第三工步最终日志出现：

```text
Stopping criterion for max diameter
NORMAL STOP
```

对应模板中的 `ODMAX`。三个模板分别使用 1200、1500 和 2100 的目标外径。

### 5.3 `STROKE` / `FORCE`：运动与载荷控制状态

对象控制段通常同时出现：

```text
STROKE       3    0.0    0.0    0.0
FORCE        3    0.0    0.0    0.0
```

它们分别记录或设置对象的行程和载荷相关状态。当前参数生成不修改 `STROKE`；`FORCE` 主要在结果导出后用于载荷提取。相同关键字在初始控制段和结果 KEY 中的上下文可能不同。

## 6. 结果提取关键字

### 6.1 `STRESS`：单元应力结果

示例头：

```text
STRESS       1    1635    0.0000000000E+000
```

当前 `_extractMaxStress`：

1. 按对象 ID 定位 `STRESS`。
2. 读取记录数量。
3. 每个记录按两行解析 6 个应力分量。
4. 计算 Von Mises 等效应力。
5. 根据 `in_progress` 选择最终帧最大值或全过程最大值。

### 6.2 `FORCE`：对象载荷/合力

结果示例：

```text
FORCE        2   -3.2454E+005    2.1790E+006    1.2811E+005
```

当前 `_extractMaxLoad` 把 `FORCE` 后面的值视为 X/Y/Z 分量，通过 `select_component` 选择：

| `select_component` | 分量 |
|---:|---|
| 0 | X |
| 1 | Y |
| 2 | Z |

`_extractMaxLoad` 会先对指定方向取绝对值。`in_progress=True` 时再求
全过程最大值；否则返回最终帧的载荷绝对值。

`FORCE` 在初始模板中也可能作为对象运动/载荷控制行出现，因此提取时应结合对象 ID 和导出 KEY 的实际结构验证。

### 6.3 `STRAIN`：单元等效应变

当 `STRAIN` 头后续记录为 `element_id effective_strain` 时，`strain_std` 读取工件
所有单元的等效应变并计算样本标准差，作为应变均匀性指标。

### 6.4 `USRELM`：用户自定义单元变量

示例：

```text
USRELM       1   13080    0.0000000000E+000       2
```

当前 `_extractUsrGrainStdv` 用它读取自定义晶粒模型的单元结果：

- 按对象 ID 定位数据块。
- 按记录数量读取后续单元行。
- 使用 `select_component` 指定列。
- 对所有单元该列数值计算标准差。

`USRELM` 本身是通用用户单元变量，不天然等于晶粒尺寸；只有在对应用户子程序约定该列保存晶粒数据时，才能作此解释。

### 6.5 `GRAIN`：DEFORM 晶粒组织结果

当前 `_extractGrainMorph` 期望头部形式为：

```text
GRAIN object_id num_units values_per_unit ...
```

它读取每个单元的组织分量，以 `select_component` 选择分量，并计算跨单元标准差。数据可能跨多行存储。

### 6.6 `USRNOD`：用户自定义节点变量

`USRNOD` 表示用户节点变量数据。当前仓库未直接用它计算目标，但在 DB 导出的终态 KEY 中通常与 `USRELM` 一起存在。

## 7. 多工步前处理动作关键字

以下关键字主要出现在仓库生成的 `transition.KEY` 中，用于在同一 DB 上切换工步。

### 7.1 `DBREAD`：读取已有 DB

```text
DBREAD 0
<db_path>
```

加载上一工步已经求解完成的 DB，使工件几何、网格、温度、应力、应变和其他状态历史继续保留。

### 7.2 `KFREAD`：读取 KEY 或 KEY 片段

```text
KFREAD 1
<key_fragment_path>
```

当前代码依次读取：

1. 下一工步 simulation 片段。
2. 工件控制属性片段。
3. 工件统一节点温度 `NDTMP` 片段（模板存在时）。
4. 对象 2～5 的完整模具片段。
5. 对象间接触片段。

### 7.3 `OBJPOS`：对象位置变换

```text
OBJPOS 1 1 dx dy dz 0 0 0 0
```

当前实现只施加平移，`dx/dy/dz` 来自前后工步工件 `CNTRAX` 中心之差。后面的旋转相关字段全部写 0。

### 7.4 `OPRNAM` / `SIMNAM`：工步与模拟名称

```text
OPRNAM
TC4 Stage 3
SIMNAM
TC4 Stage 3
```

用于给新工步设置可读名称。

### 7.5 `CURSIM`：当前模拟/工步编号

```text
CURSIM 3 3 0
```

当前多工步代码根据工步序号写入，用于标识 DB 中正在构造的 operation/simulation。

### 7.6 `GENDB`：生成或更新 DB

```text
GENDB 1 1 3
<db_path>
```

在完成工件继承、换模、定位和接触设置后，将当前前处理状态写回 DB，为下一次求解准备输入。

## 8. KEY 分段标记

以下内容以 `*` 开头，严格来说是注释，不是 DEFORM 执行关键字，但当前多工步拆分依赖它们：

```text
*  Data for Object #     1
*  Data for Object #     2
...
*  Inter-Object Data
```

当前拆分规则为：

```text
文件开头 → Object 1             = simulation
Object 1 → Object 1 首个 DIEGEO = object1_control
Object 2/3/4/5 完整段            = 下一工步模具
Inter-Object Data → 文件末尾     = 接触关系
```

如果 KEY 来自其他 DEFORM 版本、模块或导出方式，注释格式发生变化，当前正则拆分可能无法识别。

## 10. 扩展参数替换时的约定

新增可采样工艺参数时，应先判断它属于哪类结构：

1. **单行末字段**：例如 `REFTMP`、简单 `ANGMOV`，注册 `line` 原子能力。
2. **单行指定列**：编写只替换指定列的独立原子函数，不能默认替换末字段。
3. **跨多行数据块**：例如函数型 `MOVCTL`，注册 `document` 原子能力。
4. **多个参数共同决定一个数据块**：将多个参数名注册到同一个文档级能力，并保证每个样本只执行一次。

任何新关键字接入前，都应使用目标模板验证：

- 对象 ID 是否正确。
- 同一关键字是否出现多次。
- 行末字段到底是物理量、模式编号还是后续记录数量。
- 单位制是否一致。
- 修改后能否正常通过 DEFORM 前处理器生成 DB。
